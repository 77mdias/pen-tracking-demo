# Plan 07-03: Accessibility Pass — Contrast, ARIA, Keyboard

## Objective

Fix the remaining WCAG AA accessibility gaps in the hero section: a contrast failure on the CTA disclaimer text, missing ARIA attributes on decorative elements, and an `aria-label` on the hero `<section>`. After this plan, the hero is fully keyboard-navigable with visible focus states, properly labeled for screen readers, and WCAG AA contrast compliant.

## Context

**Depends on 07-01 and 07-02** because:
- 07-01 adds `aria-hidden` to `HeroCanvas` wrapper — this plan verifies the full ARIA picture is complete
- 07-02 modifies `HeroMobile` — this plan verifies mobile CTA focus states still work after the entrance animation is added

**Contrast failure (from research, computed against `#050a14`):**
- `HeroCTA.tsx` line 31: `text-zinc-600` (#52525b) = 2.56:1 ratio → **FAILS** WCAG AA 4.5:1 for normal text
- Fix: change to `text-zinc-400` (#a1a1aa) = 7.73:1 → **PASSES**

**Missing ARIA attributes:**
1. `HeroSection.tsx` line 110: `<section id="experience">` has no `aria-label` — screen readers announce it as an unnamed section
2. `HeroScrollCue.tsx`: contains visible "Scroll Down" text that screen readers will announce, but the element is `pointer-events-none` and decorative — needs `aria-hidden="true"`
3. `HeroCanvas.tsx` — `aria-hidden="true"` is being added in Plan 07-01 Task 2 ✅

**Focus states (verify only — already implemented):**
- Primary CTA: `focus-visible:ring-2 focus-visible:ring-[#ef233c] focus-visible:ring-offset-2 focus-visible:ring-offset-black` ✅
- Secondary CTA: `focus-visible:ring-2 focus-visible:ring-white focus-visible:ring-offset-2 focus-visible:ring-offset-black` ✅
- HeroMobile uses `<HeroCTA isMobile={true} />` — same focus rings ✅

**Tab order (verify only — correct by DOM order):**
- Desktop: [primary CTA button] → [secondary CTA button] (only interactive elements in hero)
- Mobile: [primary CTA button] (secondary hidden by `isMobile=true`)

## Tasks

### Task 1: Fix Contrast Failure and Add ARIA Attributes

**Objective:** Fix the `text-zinc-600` WCAG AA contrast failure on the CTA disclaimer, add `aria-label` to the hero section, and add `aria-hidden` to the decorative scroll cue.

**Files:**
- `src/components/hero/HeroCTA.tsx` — change `text-zinc-600` to `text-zinc-400`
- `src/components/hero/HeroSection.tsx` — add `aria-label` to the `<section>` element
- `src/components/hero/HeroScrollCue.tsx` — add `aria-hidden="true"` to the root element

**Implementation:**

**1. `HeroCTA.tsx` — Contrast fix:**

On line 31, find:
```tsx
<p className="font-inter text-center text-xs text-zinc-600 uppercase tracking-widest">
```

Change `text-zinc-600` to `text-zinc-400`:
```tsx
<p className="font-inter text-center text-xs text-zinc-400 uppercase tracking-widest">
```

This changes the disclaimer "Limited early access to the demo system." from #52525b (2.56:1 — FAIL) to #a1a1aa (7.73:1 — PASS). The text remains visually subordinate to the CTA button (it's smaller, uppercase, lighter) while meeting WCAG AA.

**2. `HeroSection.tsx` — Section ARIA label:**

On line 110–112, find:
```tsx
<section
  ref={sectionRef}
  id="experience"
```

Add `aria-label`:
```tsx
<section
  ref={sectionRef}
  id="experience"
  aria-label="Hero — Join the Private Beta"
```

This gives screen readers a meaningful name for the section landmark. The label matches the primary CTA action.

**3. `HeroScrollCue.tsx` — Decorative ARIA hidden:**

On line 5, find:
```tsx
<div className="hero-scroll-cue absolute bottom-10 left-1/2 -translate-x-1/2 z-[20] flex flex-col items-center gap-2 pointer-events-none">
```

Add `aria-hidden="true"`:
```tsx
<div className="hero-scroll-cue absolute bottom-10 left-1/2 -translate-x-1/2 z-[20] flex flex-col items-center gap-2 pointer-events-none" aria-hidden="true">
```

The scroll cue is purely decorative (`pointer-events-none`, no interactive elements) and is hidden for `reducedMotion` users. Screen readers should not announce "Scroll Down" text — it provides no actionable information for keyboard/screen reader users.
