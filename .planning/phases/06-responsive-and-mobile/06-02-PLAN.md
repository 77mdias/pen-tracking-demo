# Plan 02: HeroSection Routing + HeroContent Cleanup

**Phase:** 06 — Responsive and Mobile
**Plan:** 06-02

## Goal

Wire `HeroMobile` into `HeroSection` so mobile devices receive the new CTA-first layout, and clean `HeroContent` of all `isMobile` logic since it is now tablet+desktop only.

This plan has two tasks that must both complete before verification.

## Status

Active

## Pre-conditions

- `06-01-PLAN.md` is complete: `src/components/hero/HeroMobile.tsx` exists with the new implementation ✅
- `src/components/hero/HeroSection.tsx` currently passes `isMobile={isMobile}` to `HeroContent` (line 127) — this is the exact line to replace
- `src/components/hero/HeroContent.tsx` currently has `isMobile?: boolean` prop and an `isMobile` ternary for subheadline copy — both must be removed

## Tasks

### T1: HeroSection.tsx — add import + replace HeroContent render

**File:** `src/components/hero/HeroSection.tsx`
**Type:** modify (2 surgical changes)

#### Change 1 — Add HeroMobile import

**Before (line 6):**
```tsx
import HeroContent from "@/components/hero/HeroContent";
```

**After:**
```tsx
import HeroContent from "@/components/hero/HeroContent";
import HeroMobile from "@/components/hero/HeroMobile";
```

#### Change 2 — Replace HeroContent with routing conditional (line 127)

**Before (lines 127):**
```tsx
          <HeroContent isMobile={isMobile} isTablet={isTablet} />
```

**After:**
```tsx
          {isMobile ? (
            <HeroMobile reducedMotion={reducedMotion} />
          ) : (
            <HeroContent isTablet={isTablet} />
          )}
```

**Notes:**
- The surrounding `<div>` with its mobile/tablet/desktop padding conditionals (lines 119–126) is **unchanged** — those classes (`items-start pt-24 pb-12` for mobile) still apply correctly to the wrapper that contains `HeroMobile`
- `reducedMotion` is already in scope at the HeroSection level (line 37: `const reducedMotion = useReducedMotion()`) ✅
- `isMobile`, `isTablet`, `reducedMotion` are all already in scope ✅

---

### T2: HeroContent.tsx — remove isMobile prop and ternary

**File:** `src/components/hero/HeroContent.tsx`
**Type:** modify (2 surgical changes)

#### Change 1 — Remove isMobile from type and destructuring

**Before (lines 5–13):**
```tsx
type HeroContentProps = {
  isMobile?: boolean;
  isTablet?: boolean;
};

export default function HeroContent({ isMobile = false, isTablet = false }: HeroContentProps) {
  const subheadline = isMobile
    ? "Premium writing precision with an intelligent layer built for focus."
    : "A premium writing experience designed around precision, focus, and a new intelligent layer of control.";
```

**After:**
```tsx
type HeroContentProps = {
  isTablet?: boolean;
};

export default function HeroContent({ isTablet = false }: HeroContentProps) {
  const subheadline = "A premium writing experience designed around precision, focus, and a new intelligent layer of control.";
```

#### Change 2 — Remove isMobile from HeroCTA call

**Before (line 50):**
```tsx
      <HeroCTA isMobile={isMobile} />
```

**After:**
```tsx
      <HeroCTA />
```

**Notes:**
- `HeroCTA` has `isMobile?: boolean` with default `false`, so omitting the prop is type-safe ✅
- The desktop subheadline copy is the canonical copy; the mobile copy is now exclusively owned by `HeroMobile`
- All other content in `HeroContent` (badge, headline split lines, support copy, `hero-support-copy` placeholder) is **unchanged**

**TypeScript contract check:**
- `HeroContent` no longer exports `isMobile` in its props type — TypeScript will error if any other caller still passes `isMobile` to `HeroContent`. As of Phase 6, only `HeroSection` calls `HeroContent`, and T1 removes that usage.

**Visual check (requires dev server):**
- Mobile (375px): hero shows HeroMobile CTA-first layout (badge → CTA → headline → subheadline)
- Tablet (768–1023px): hero shows HeroContent with `max-w-4xl` container, desktop subheadline copy
- Desktop (≥1024px): hero shows HeroContent with `max-w-5xl` container, desktop subheadline copy
- The outer container padding (`pt-24 pb-12` on mobile, `py-10` on tablet, no padding override on desktop) still applies correctly in all three cases

## Threat Model

| Regression | Risk | Mitigation |
|---|---|---|
| Another file calls `<HeroContent isMobile={...}>` and breaks build after T2 | Low | TypeScript strict mode surfaces this as a type error at build time — the build step in Verification catches it |
| `reducedMotion` not in scope in HeroSection when `<HeroMobile reducedMotion={...}>` is written | None | `reducedMotion` is defined on line 37 of HeroSection via `useReducedMotion()` ✅ |
| Outer container padding lost because it was conditional on `HeroContent` rendering | None | The padding lives in the `<div>` wrapper (lines 119–126), not inside `HeroContent` — the conditional renders inside the same wrapper ✅ |
| `HeroAmbientDetails` and `HeroScrollCue` still gated by `!isMobile` | None | Those gates (lines 130–131) are unchanged — they correctly remain hidden on mobile ✅ |
| `useHeroTimeline` enter animation fails on mobile because `.hero-headline-line` split-line structure differs from HeroMobile | Medium | `HeroMobile` uses plain `<span className="block">` without the `split-line`/`hero-headline-line` wrapper pattern. The enter animation targets `.hero-headline-line` which only exists in `HeroContent`. On mobile, `enableScrollNarrative=false` and the fallback path in `useHeroTimeline` runs `gsap.set(... opacity:1, y:0 ...)` on all selectors — missing selectors are silently skipped by GSAP. The headline in `HeroMobile` starts visible with no clip needed, so this is correct behavior. |
