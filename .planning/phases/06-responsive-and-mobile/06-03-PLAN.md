### ✅ useHeroTimeline — no tablet-specific treatment needed

`useHeroTimeline` uses GSAP class selectors (`.hero-headline-line`, `.hero-subheadline`, `.hero-cta`, etc.). These target the same DOM elements on tablet as on desktop. The enter animation (from opacity/y to final state) is identical in both cases — appropriate since the tablet layout uses the same visual hierarchy as desktop, just compressed via CSS classes.

The scroll narrative (`enableScrollNarrative`) is **active on tablet** (`!reducedMotion && !isMobile && !shouldUseFallback` — isTablet does not gate it). This is correct: tablet users get the full scroll narrative at reduced 3D amplitude (0.65). The GSAP scroll-driven opacity/scale values are dimensionless ratios and scale naturally with the layout.

**Verdict:** No DOM animation gaps on tablet. No changes needed.

### ✅ HeroCanvas DPR — tablet uses native recommendedMaxDpr

```tsx
// HeroSection.tsx line 102
maxDpr={isMobile ? Math.min(recommendedMaxDpr, 1.5) : recommendedMaxDpr}
```

Tablet uses `recommendedMaxDpr` directly (no cap). On a typical 2x tablet, `recommendedMaxDpr` resolves to 1.25 (tier medium) or 1.5 (tier high). Appropriate.
