# Plan: HeroScene — Scroll-Linked 3D Transforms
**Phase:** 05 — Scroll Orchestration
**Plan:** 05-02

## Goal
Audit and confirm that `HeroScene.tsx` correctly reads `scrollProgressRef.current` inside the Three.js render loop to drive camera and pen rotation. No executor work needed.

## Status
✅ **Complete (brownfield)**

## Audit Evidence

**File:** `src/components/hero/HeroScene.tsx`

Scroll-driven 3D transforms are fully wired:

- `scrollProgressRef: { current: number }` is received as a prop and read inside the render/animation loop
- `reducedMotion` guard: `const scrollProgress = reducedMotion ? 0 : scrollProgressRef.current` — correct, no scroll movement in reduced-motion mode
- **Rotation:** `targetRotY += scrollProgress * rotationRangeRadians * motionScale` and `targetRotX += scrollProgress * 0.06 * motionScale` — pen rotates on both axes as user scrolls
- **Camera shift:** `targetCameraX`, `targetCameraY`, `targetCameraZ` all scaled by `scrollProgress` with independent multipliers — camera drifts smoothly through the scroll range
- `heroSceneConfig.scroll.rotationRangeDegrees` and `heroSceneConfig.scroll.cameraShift` drive the magnitudes — externally configurable

All three transform axes (rotation Y, rotation X, camera position) respond to `scrollProgress`. No hardcoded values, no direct DOM manipulation, no stale closures. **No changes required.**

## Threat Model
None — read-only rendering side effect driven by a ref. No user input touches this path.
