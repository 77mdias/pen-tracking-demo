### T2: Fix support copy animation timing
**File:** `src/hooks/useHeroTimeline.ts`
**Type:** modify

**Locate this exact line inside `applyScrollProgress` (line ~79):**
```ts
setSupportCopyOpacity(Math.min(1, progress * 3) * fadeOut);
```

**Replace that single line with these three lines:**
```ts
const supportCopyFadeIn = Math.max(0, Math.min(1, (progress - 0.20) / 0.20));
const supportCopyFadeOut = Math.max(0, Math.min(1, (0.60 - progress) / 0.20));
setSupportCopyOpacity(supportCopyFadeIn * supportCopyFadeOut);
```

**What this changes:**
| Scroll % | Old behavior | New behavior |
|----------|-------------|--------------|
| 0–20% | Fades in immediately | Invisible (opacity 0) |
| 20–40% | Already fading out with headline | Fades in (0 → 1) |
| 40% | Near-zero, gone | Fully visible (opacity 1) |
| 40–60% | Gone | Fades out (1 → 0) |
| 60%+ | Gone | Invisible (opacity 0) |

**Do NOT touch** any other line in `applyScrollProgress` — headline, subheadline, CTA, and scroll-cue timings are correct and must not change.

## Threat Model
- **Regression risk — other elements:** Only `setSupportCopyOpacity` is modified; all other `gsap.quickSetter` calls in `applyScrollProgress` are untouched. Low risk.
- **Regression risk — reduced-motion path:** The `reducedMotion` guard branch sets all elements to `opacity: 1` via `gsap.set` before any scroll logic runs and returns early — the new timing logic is never reached in reduced-motion mode. No impact.
- **GSAP ticker performance:** Two additional `Math.max/min` calls per tick (~60/s). Negligible cost.
- **`opacity-0` class on element:** Tailwind sets `opacity: 0` at paint time; GSAP overrides it at runtime via inline style. The class must stay so there is no flash of visible text before GSAP initializes.
